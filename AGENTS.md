# Agent guide

Personal portfolio site: TanStack Start (React 19, SSR) + Supabase (via Lovable
Cloud) + Tailwind CSS 4 + shadcn/ui. This file is the single source of truth for
AI coding agents; `CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md`
only point here.

## Commands

Use Bun (`bun.lock` is the lockfile); npm works too.

| Task | Command |
| --- | --- |
| Install | `bun install` |
| Dev server | `bun run dev` |
| Lint | `bun run lint` |
| Tests | `bun run test` |
| Type check | `bunx tsc --noEmit` |
| Build | `bun run build` |

Before you finish any code change, run lint, the type check, the tests and the build. See
`.agents/skills/verify-changes/SKILL.md`. Existing code has many Prettier lint
errors (a known baseline), so lint the files you changed (`bunx eslint <files>`)
and keep those clean. Do not reformat the whole repo in an unrelated change.

## Project rules
- Projects, experience and skills live in Cloud tables, read via public server fns in `src/data/portfolio.functions.ts` and exposed as queryOptions in `src/data/index.ts`; profile lives in the single-row `site_profile` table (static `src/data/profile.ts` is only a fallback). Writes are admin-only (`has_role`) so signed-up visitors can't edit content.
- Each portfolio section is its own route with its own head(); shared header/footer wrap `<Outlet />` in `__root.tsx`.
- Admin lives at `/admin` (layout `admin.tsx`, client-only `beforeLoad` gate → `/admin/login` via un-nested `admin_.login.tsx`); writes go through the browser client so RLS `has_role('admin')` is the real guard. Migration `0005_security_hardening.sql` removed the old first-sign-up-becomes-admin trigger; admins are granted only by inserting into `public.user_roles`. Public sign-up is off.
- Site content (projects, experience, skills, profile text) is data, not code. Do not hard-code content into components or edit `src/data/profile.ts` to change what the live site shows; it is changed in the admin UI.

## Conventions
- Routing is file-based in `src/routes/` (read `src/routes/README.md`). Every public route has `head()` with title, description, `og:title` and `og:description`, built with `pageTitle()` and `loadSiteIdentity()`.
- Data flow for a public page: server fn in `portfolio.functions.ts` → `queryOptions` in `src/data/index.ts` → `context.queryClient.ensureQueryData(...)` in the route `loader` → `useSuspenseQuery` in the component.
- Server fns select explicit column lists (never `*`) and throw a generic `Error` message, not the raw Supabase error.
- Shared types live in `src/data/types.ts`. Use the `@/` import alias for `src/`.
- Styling: Tailwind utility classes and the design tokens in `src/styles.css`. Keep the look editorial and minimal: 1px borders, monospace for dates, tags and indices, one accent colour (`text-primary`). Reuse `Page` and `SectionHeader` from `src/components/site/primitives.tsx`.
- Formatting follows `.prettierrc`; run `bun run format` on files you touched if needed.

## Do not edit by hand
- `src/routeTree.gen.ts`: generated by the TanStack router plugin.
- `src/integrations/supabase/types.ts` and `client.ts`: generated by Lovable Cloud.
- `src/components/ui/*`: shadcn/ui components. Add new ones with the shadcn CLI, and wrap rather than fork.
- `drizzle/schema.ts`, `drizzle/migrations/meta/*`: generated.
- Migrations already in `drizzle/migrations/`: they are applied. Add a new one instead of editing an old one.
- `.lovable/`: Lovable's own files.
- `vite.config.ts` plugins: `@lovable.dev/vite-tanstack-config` already includes them, and adding them again breaks the build.

## Security rules
- Every new table: `ENABLE ROW LEVEL SECURITY`, explicit `GRANT`s, a public read policy only if the data is public, and an `"Admins manage"` policy using `public.has_role(auth.uid(), 'admin')`.
- Never use or expose a service-role key in client code or `VITE_*` variables. `.env` holds only the publishable key.
- User-supplied URLs must be `https://`: validate them with `isSafeUrl()` from `@/lib/utils` in forms and before rendering, add a DB CHECK constraint, and open external links with `target="_blank" rel="noreferrer"`.
- No `dangerouslySetInnerHTML`. Markdown is rendered with `react-markdown`.

## Git
- Commit to `main` only in a working state: type check, tests and build pass, and the files you changed lint clean.
- Never force-push or rewrite pushed history (see the Lovable note above).
- Write commit messages in the imperative mood ("Add …", "Fix …").
